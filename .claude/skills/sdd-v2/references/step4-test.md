# 第④步 测试:本地场景测试 + 收尾(state 报"全部交付"后)

## 本地场景测试

**定位(五层测试体系)**:本步的场景脚本只负责**跨接口业务链路**(L4,分母=验收 A);接口级行为归 L3(已随各 feature 交付对账过,`_work/api-tests/`),静态守卫归 L1,单测归 L2,浏览器主链归 L5。场景不重复造接口用例。全量回归= L3 全套 + L4 全部场景 + L5 冒烟,三层一起重跑。

1. 派 local-tester 类子代理:**逐 feature 派发**(先例:casebook#场景测试只跑头一个——整批打包给一个代理,F001 跑完遇红走了修复回路,其余 19 个只生成脚本未执行),每次给一个 spec 目录 + impl-config + 本地启动步骤文档;该 feature 的 L4 报告落档才派下一个。**开口两步前置**(复盘 2026-09-19):
   - **债务汇总**:先汇总 `specs/_work/debt-register.md`(step3 逐条登记的遗留申报)成核对清单——缺表则此时补建,条目取自各 impl 日志"遗留问题"段
   - **L5 分母核对**:对照 feature-list 页面清单核对 `tests/e2e/` 冒烟矩阵,页面×主链有缺即列缺口(不进全量回归,先补冒烟)
2. 按验收 A 生成/执行场景,报每条 A 红绿;失败清单逐条发回对应实现代理修
3. 修复后:受影响 feature 重跑自查 + 评审复核,受影响场景重测;**修复过程中不整批全量回归**,只重跑受影响场景+一条冒烟链
4. **红单清零后的最后一轮才全量回归**:L3 全套(`_work/api-tests/`,豁免条目除外)+ L4 全部场景脚本(`_work/local-tests/`,不只最后改动涉及的)+ L5 浏览器冒烟(见 guard-tests.md §3.2),三层重跑全绿,命令与退出码记日志;冒烟红按测试失败处理
   - **走查类验收证据固定格式**:`入口/路径 × 触发次数 × 截图或代码行号`——禁止"通过(代码走查)"一句带过(案例:casebook#走查偏乐观)
   - **run.sh 规范**:退出码用重定向捕获(`cmd > log 2>&1; echo $?`),禁止 `cmd | tail` 类管道掩盖真实退出码(案例:casebook#管道掩盖退出码)
   - **report 由脚本生成,禁止手写**:每个 feature 的 `_work/local-tests/<F>/report.md` 由该 feature 的 run.sh **执行时**自动落盘(逐断言结果 + 实跑退出码);没跑就没有报告。AI 手写/事后补写的报告不算凭证——done 闸按 report.md 逐 feature 对账,缺一即红(casebook#场景测试只跑头一个)
5. 回归全绿后场景脚本归档到章程"测试策略"登记目录(默认 `tests/e2e/`)
6. 同一问题修 3 次仍红→停呈用户(红线);环境起不来单独呈报不算测试失败,环境未就绪不得宣布通过

判据:每 feature 每条验收 A 绿,红单清零,全量回归绿并归档。

python scripts/sdd.py <specs> --stage done   # 必须全绿
