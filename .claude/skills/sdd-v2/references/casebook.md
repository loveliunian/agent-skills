## 枚举超宽(Q011)

枚举/状态字段的最长取值字符数超过 varchar 宽度(EXPIRE_DISABLE 14 字符 vs varchar(10)),实现期写入即截断/报错。详设的组合性矛盾,解析期静态可查。
**催生机制**:step1 §5 三表对账·枚举长度检查。

## 字段差集漏列(Q013)

接口出入参字段在表结构中无对应列(usr_user 漏 main_post_id),写契约时才发现缺列,倒逼回头翻详设(违规)。
**催生机制**:step1 §5 三表对账·字段差集;R-J 字段口径一致性(spec tables[].fields 与详设 twin 逐列比对)。

## 唯一索引×逻辑删除互斥(Q017/Q018)

「删了重插」语义的表走逻辑删除:软删行占住业务列唯一索引,同键重建必撞 DuplicateKeyException 500(先例:编辑用户角色集合不变时 500)。同族三例。
**催生机制**:step1 §5 三表对账·互斥扫描;step2「删了重插」三选一裁决;guard-tests §2.6 DDL 互斥守卫;守门引擎 UNIQUE×重建语义 WARN。

## 注释绕守卫(G6)

DDL 守卫解析建表体时未剥 SQL 注释,注释中的 `);` 被误判为建表截断,连续两代 feature 靠改注释的方式绕行守卫而不是修解析器。
**催生机制**:guard-tests §2.6「解析器须先剥注释」;复盘四问"哪道校验没拦住"。

## 种子桩污染(V7)

迁移里的占位种子行(ext_* 桩表)污染了其他 feature 的候选计数(F006),跨 feature 数据耦合。
**催生机制**:guard-tests §2.6 种子行快照断言(新迁移不得增删改既有种子行)。

## 类型错误运行时爆发

ESLint 与 esbuild 均不查类型:`defineProps<{...}>` 漏写调用括号、字段名与契约不符,vite build 全绿,运行时整页崩溃(组织详情页)。
**催生机制**:guard-tests §3.1 vue-tsc 类型检查(必选)。

## 首屏链路断裂

根节点上「新建子组织」入口置灰,「建组织→建用户」整条链断;后端测试全绿未暴露——接口级验证替代不了首屏初始态的入口链路走查。另:spec 只写"根无停启"(A19),漏了"根必须有新建入口"。
**催生机制**:step3「前端入口链路走查」自查(首屏初始态出发/边界实体能力矩阵);守门引擎"任务含前端但验收全是接口口径"WARN。

## 单边状态对称(F003/F004-REV)

状态类逻辑只验了一个方向:启用方向部分失败静默(F004-REV-1)、停→启无处理(F003-REV-1)。
**催生机制**:step3「单边状态对称」自查项。

## 占位登记延迟(组B)

并行批次中 4 例 `[Q-Fxxx-nn]` 占位只记 impl 日志、延迟登记 open-questions.json,全靠评审人肉抓。
**催生机制**:deliver 闸的占位对账(ERROR);C1 占位对账接入交付检查。新占位统一用 `[Qnnn]` 三位编号,`[Q-Fxxx-nn]` 为历史格式仅兼容识别。

## 走查偏乐观(A12/A15/A3)

三条走查类验收用"通过(代码走查)"一句带过,均被评审打回。
**催生机制**:step4 走查证据固定格式(入口/路径 × 触发次数 × 截图或行号)。

## 管道掩盖退出码

首轮回归的 run.sh 用 `cmd | tail` 类管道取输出,真实退出码被管道吞掉,失败被漏报。
**催生机制**:step4 run.sh 规范(重定向捕获 `cmd > log 2>&1; echo $?`)。

## 并行撕裂

早期并行无契约:共享本地 Maven 仓库的 common jar 被并行 install 写坏(`ZipFile invalid LOC header`)、共享库 Flyway checksum 错位、无版本控制的软隔离目录编译两度被打断、误报循环十余轮。
**催生机制**:references/parallel-worktrees.md 三条硬约束(common 串行先行/副本禁 install 禁连库/规范材料走主检出绝对路径);step3 pipeline.json 契约(迁移号独占/文件所有权/测试环境隔离);SKILL 规则 6 并行分级。

## 场景测试只跑头一个(F002~F020)

step4 场景测试整批打包给一个 local-tester 代理("本批 spec 目录"):代理先跑了 F001,遇红(exit 4)按流程发回修复;修复回路走完后主会话直接跳去全量回归,F002~F020 只生成了 run.sh **从未执行**。当时 done 闸只查 local-tests 目录非空、不查执行凭证,缺口畅通无阻;回归报告声称 20 组全绿也无逐 feature 报告可核验。L5 分母核对"缺即补冒烟"亦被一句"以 L3+L4 承接"自我豁免。
**催生机制**:step4 §本地场景测试第 1 条"逐 feature 派发,报告落档才派下一个";step4"report 由脚本生成,禁止手写"(run.sh 执行时自动落盘,没跑就没报告);守门引擎 done 闸 L4 凭证对账(每 feature report.md 必须存在且含 exit 0 实跑记录)。
