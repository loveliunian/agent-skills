# PRD-Lite 独立对账清单(对账 agent 合同)

> 你是独立上下文对账 agent:**不参与改写、只读不改 drafts**。发现问题的处置是"登记进问题清单",不是边查边改。
> 判据合同:`.prd-lite/extraction-rules.md`。对账对象:`slices/*.md` vs `drafts/*.md`(+ front/附录)。
> 结论分级:**丢事实 / 编造 / 语义漂移 / 溯源缺口**(阻塞交付)+ 提示级观察(建议处理)。
> 产出:`audit/audit-<X>.md`,含方法、样本量、问题清单、通过项清单、处置优先级。

## 一、脚本全量比对(先机检,后人核)

1. **编号集合完整性**:R / Q / DEC / U / FUN / REQ / FP / REL / EVD 等逐类提取去重,原文 vs 草稿双向差集。注意排除假阳性(如 `REQ-` 命中 `Q-`、编号落在章级元数据段)。
2. **三类整表行数守恒**:字段表、业务规则表、验收标准表逐 FUN 比对行数(原/稿)——应逐行相等或经授权合并,合并须逐项核验无事实损失。
3. **行键比对**:字段名首列、规则编号首列逐行位置对应且一致(归一化全半角括号后 0 差异)。
4. **数值表达式反向核对**:从草稿抽全部数值/阈值/枚举,逐一回原文检索;未命中项逐条人工判定是假阳性、合法压缩还是丢值。
5. **提示文案反向核对**:草稿全部带引号字符串逐一回原文子串检索——未命中且原文确无 = **编造**(含措辞编造:事实在原文但提示措辞系自造)。
6. **装配自检复跑**:只读运行 assemble.py 至临时目录,核对 FUN 数、R 覆盖、未决域数、溯源附表覆盖。

## 二、人工逐行抽核(机检测不到的语义层)

7. **语义逐行比对**:分支/异常行、主流程步骤逐条计数与语义比对;低分/并/拆行逐条人工复核,判定是"行合并/列删减"还是丢事实。
8. **mermaid 落点核验**:被删图的**全部判定节点**逐节点在草稿正文定位;定位不到 = 删图失真。保留图做节点级逐字比对。
9. **【待确认】映射**:原文出现点枚举 → 未决条目映射,核对 0 项遗漏;无未决项的域核对"0 条"声明真实。
10. **跨域一致性抽查**:记号(`↔`、`不适用`)、层级表述(FP 层 vs 泛化)、合同授权口径是否跨域一致。
11. **front 总表抽核**:FUN 总表逐行、REL/FLW/DEC 表抽行,与原文对应章节逐格比对。

## 三、判定与产出

- 任何一项"丢事实/编造/语义漂移/溯源缺口"≠ 0:交付被阻断,列出逐条处置建议(必改/建议/可选)。
- 提示级观察(如低风险瑕疵、口径建议)单列,不阻塞但建议落修。
- **禁止**:修改 drafts、顺手订正、以"改写 agent 声称"为通过依据——只核产物,不核声称。
