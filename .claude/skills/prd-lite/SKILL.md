# PRD → PRD-Lite(开发交接版)

把一份大而全的 PRD(数千行,含大量模板占位与溯源编号链)重排成开发直接可读的 Lite 版。核心承诺:**降维不失真**——压缩率 30~40%,事实保留率 100%,且这个"100%"必须由独立对账证明,不得自证。

## 目录结构(自包含)

```
.claude/skills/prd-lite/
├── SKILL.md              本说明 + 方法论 + 执行流程
├── rules-card.md         改写规则卡模板(合同;按目标 PRD 填定制项后生效)
├── audit-checklist.md    独立对账 agent 的核对清单(反向验证合同)
└── scripts/
    ├── split.py          按 F 域切片 + 提取 FUN 清单 → slices/ + manifest.json
    └── assemble.py       拼装草稿 + 规则索引/未决问题汇总 + 守恒自检
```

运行期工作目录约定为 `PRD 同目录下 .prd-lite/`:`slices/`(原文切片)、`drafts/`(改写草稿)、`audit/`(对账留痕)、`config.json`(本次定制项)。

## 核心原则:AI 出语义层,脚本守守恒层

| 层 | 执行者 | 内容 |
|---|---|---|
| 语义层 | AI(精读原文) | 按 rules-card 逐 FUN 改写:删样板、并重复、压措辞、摘未决项 |
| 守恒层 | `assemble.py` | FUN 数守恒、规则编号全集覆盖、未决问题域齐收——**机检不过禁止装配交付** |
| 验证层 | 独立对账 agent | 按 audit-checklist 反向核对(脚本全量比对 + 人工逐行抽核),只出问题清单不改稿 |

与 prd-detail-design / flow-node-panorama 同一分工哲学:**凡脚本能确定性判定的,不靠 AI 自觉;凡自检能守住的,不靠对账兜底;对账只查脚本查不了的事实层。**

## 三条铁律(规则卡第 0 节的浓缩,违反即返工)

1. **事实零改动**:字段、规则、阈值、提示文案、流程语义必须与原文一致;允许删冗余/改组织/压措辞,禁止编造、模糊化("等等/类似/如有必要"零容忍)、把"待确认"当定稿。
2. **编号一个不丢**:R 规则 / Q 疑点 / DEC 决策 / U 未决 / FUN 编号,内容可摘出移位,编号必须出现在草稿某处。原文自相矛盾的编号引用(如错位一档)**原样保留并在未决节登记,禁止顺手订正**——订正属于裁决,不在改写授权内。
3. **对账独立且只读**:对账 agent 不得参与改写、不得修改 drafts;发现问题的处置是"登记 → 主会话修 → 重装配 → 复对",不是对账 agent 边查边改。

## 执行流程(五阶段,不可跳步)

### 阶段一:切片建图

1. 通读 PRD 目录结构,识别功能域划分(F0x 域 / 前置章节 / 附录);
2. 在 `.prd-lite/config.json` 填配置(域清单、FUN 标题正则、规则编号正则、装配顺序),跑 `split.py` 产出 `slices/` 与 `manifest.json`(含每片起止行、行数、FUN 清单);
3. 清点原文锚点:FUN 总数、R 编号范围、Q/DEC/【待确认】分布——这是后面守恒自检的基线。

### 阶段二:定合同

把 `rules-card.md` 模板按本次 PRD 的信息项结构定制(信息项逐项处置表、FUN 输出骨架、篇幅目标、禁止事项),存 `.prd-lite/extraction-rules.md`。**合同必须先于改写定稿**,两个口径矛盾处(如"图保留"vs"图可删")在合同内消解,不留改写 agent 自选——历史教训:口径冲突会导致不同域 agent 选取不同侧,产物口径漂移。

### 阶段三:逐域改写

- 每个 F 域草稿一个独立上下文(可并行),输入=切片+合同,输出=`drafts/F0x.md`(front、appendix 同理);
- 严格按合同的 FUN 骨架输出(空节省略),域末固定 `## 本域未决问题`(无也写"0 条")与 `## 溯源附表` 两节——装配脚本依赖这两节采集;
- 草稿中所有从正文摘除的【待确认】逐条编号 U-<域>-<序>,原文已有 Q-xxx 的沿用原编号。

### 阶段四:装配自检

跑 `assemble.py` 产出 PRD-lite.md,自检四项全过才算装配成功:

```
FUN 标题数 == 原文 FUN 总数
规则编号覆盖 == slices 全集中出现过的 R 编号(缺一即 FAIL)
未决问题域数 == 域总数(静默缺域 = 有草稿漏了固定节)
溯源附表覆盖全部 FUN
```

### 阶段五:独立对账 → 修正 → 复装

1. 委托独立对账 agent(不参与改写),按 `audit-checklist.md` 对全部域做反向核对,产出 `audit/audit-<X>.md`(问题清单按 丢事实/编造/语义漂移/溯源缺口 + 提示级观察 分级);
2. 对账结论只有"零丢零造"才可交付;有问题的逐条落修(必改/建议/可选分级处置),修完**重新装配并复验自检**;
3. 对账留痕(audit/*.md、比对脚本输出)随交付物归档——"100% 保留"的声称必须可被下游独立复核。

## 历史教训(已固化进合同与清单,复用时直接规避)

- 篇幅目标要按"整表搬运行不计入压缩"重算,否则合同自相矛盾、产物必然超标被误判;
- 删列(如分支表的流程指针列)必须在合同显式授权,未授权的删列就是口径漂移;
- 节名占位、`—`/`不适用` 等记号要跨域统一,装配后全表一致性才成立;
- 改写 agent 声称的"落点表/对照表"若不在产物中,等于没做——对账时要核产物,不核声称。
