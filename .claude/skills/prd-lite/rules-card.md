# PRD-Lite 提取规则卡(模板)

> 本卡是改写 agent 的合同。执行时**逐条对照**,不做卡外自由发挥。
> 目标:把"完备性优先"的机器版 PRD 降维重排成"重点优先"的开发交接版。
> **事实零改动**:所有字段、规则、阈值、流程语义必须与原文一致;只允许删冗余、改组织、压措辞,**禁止编造与改变语义**。
> 使用方法:复制本模板到 `.prd-lite/extraction-rules.md`,按目标 PRD 填写 `【定制】` 标记处;合同内部口径必须自洽,不得留二选一给改写 agent。

## 0. 三条总原则

1. **可追溯性降级不删除**:REQ/FP/REL/EVD/DEC/CG【定制:按本文档实际编号体系】编号链从正文全部摘除,集中到本域草稿末尾的"溯源附表"(一张表:FUN → 关联 REQ/FP → EVD/DEC)。R-xxx 规则编号**保留**(开发要按它对齐),但正文引用处只写成对时的 `(R-005)`,叙述句里不再出现。
2. **一处一事实**:同一约束在"概述/边界/流程/分支"里重复出现的,只在最贴近开发者执行点的那一节保留一次(通常是"界面与交互"或"业务规则")。
3. **样板清零**:"无"、"不适用,并说明原因:…"、"逻辑补全说明:无"、"本节同第X章口径" 等模板占位句一律删除;该信息项整体为空则整节省略。
4. **原文矛盾不代裁**:原文自相矛盾的编号引用或口径(如 R 号错位一档),**原样保留**并在本域未决问题节登记"原文即矛盾,Lite 不代裁";订正属于裁决,不在改写授权内。

## 1. 信息项逐项处置【定制:按目标 PRD 的信息项结构重排】

| 原文信息项 | 处置 | 输出到 |
| --- | --- | --- |
| 1 功能概述与预期结果 | 压成 1–2 句人话(谁/在哪/做什么/达成什么) | `### 是什么` |
| 2 关联需求与设计依据 | **整节删除**,内容进溯源附表 | 附表 |
| 3 功能边界 | "包含"并入`是什么`;"不包含"只保留**容易越界**的 1–3 条 | `### 是什么` 尾注 |
| 4 界面结构与交互 | **全文重点,最大保留**。删导航路径复述、删与其他 FUN 重复的区域描述(改为"同 FUN-xxx");【待确认】摘出留占位 | `### 界面与交互` |
| 5 权限能力约束 | 保留(可见/可操作/数据范围三口径) | `### 权限` |
| 6 触发条件或入口 | 并入`是什么`一句 | — |
| 7 前置条件 | 非平凡的前置保留一行,模板式"已登录"删除 | `### 前置` |
| 8 主流程与操作流程图 | 步骤编号列表保留;**mermaid 图**:业务流程闭环图**保留**(每个 FUN 的核心操作至少一张,删除前置校验/阶梯判定/批量执行这类含分支决策的链路优先),纯页面跳转图删。保留/恢复图时:节点文字零改动,剥离 REL/DEC 编号,保留 R-xxx 与 FUN-xxx 标注,禁止画新图 | `### 主流程` |
| 9 业务分支 | 与 10 合并成一张表;**只保留会改变用户操作或系统结果的行**;跨 FUN 跳转分支压成一行"→ FUN-xxx";流程指针列/回归位置列**显式授权删或留** | `### 分支与异常` |
| 10 异常处理 | 同上;"处理方式/恢复方式"合并为一列;提示文案保留 | `### 分支与异常` |
| 11 业务规则 | **原样保留表格**(规则标识/场景/判定/结果;删与判定重复的触发列)。此节将被全局规则总表汇总,格式必须保持标准表格 | `### 业务规则` |
| 12 状态定义与状态转移 | 有状态机的 FUN 保留(表或一句话);"无状态"删除 | `### 状态与联动` |
| 13 结果与状态变化 | 与 12 合并;重点是**联动刷新口径**(保存后哪些视图刷新) | `### 状态与联动` |
| 14 数据字段 | **全文重点,最大保留**。字段表压缩列;溯源列删;"待确认"字段摘出并在表中标 `⚠待裁决`;**字段名本身不得压缩改写**(原文括注如"触发条件(策略区 1)"原样保留,防止下游按字段名匹配失效) | `### 字段` |
| 15 验收标准 | 全保留(开发直接当 DoD 用) | `### 验收标准` |
| 16 上游依赖 | 压成 FUN 依赖一行列表 | `### 上下游` |
| 17 下游影响与后续触发 | 同上合并 | `### 上下游` |

**跨域记号统一**(装配后全表一致性):必填列空值统一写 `不适用`;关系符(如 `↔`)不得省略;字段名括注压缩规则全表一致。

## 2. 容器级内容处置

- 每域只写**一段 3–5 句的域导读**(页面有哪些 Tab/区、子模块到 FUN 的对应一句话),子模块容器说明全删。
- 域内子模块不再作为输出层级;FUN 按域顺序平铺,子模块归属写进 FUN 标题行括注:`## FUN-0xx <名称>(<子模块> · <承载页面/位置>)`。

## 3. 待确认项处置(强制)

- 正文中所有 `【待确认:…】` 从原句摘出,原句改写为不依赖该悬而未决信息的表述 + `⚠(见 U-xx)`。
- 摘出的问题在本草稿末尾 `## 本域未决问题` 逐条编号列出:`U-<域号>-<序>` + 原文位置 + 问题内容 + 是否阻塞实现(依原文"消解前不得定稿"判定)。原文已有的 Q-xxx 编号**沿用,不自造**。
- **无未决项的域也必须写该节**,内容为"本域无未决问题"(装配脚本按节采集,缺节即漏采)。

## 4. FUN 输出骨架(严格照此结构,供装配脚本解析)

```markdown
## FUN-0xx <名称>(<子模块> · <承载页面/位置>)

### 是什么
### 界面与交互
### 字段
### 主流程
### 分支与异常
### 业务规则
### 状态与联动
### 权限
### 前置
### 验收标准
### 上下游
```

空节直接省略节标题。草稿级固定节:`# F0x <域名>` + 域导读 + 各 FUN + `## 本域未决问题` + `## 溯源附表`。
【定制:按目标 PRD 的 FUN 编号规则与标题格式改写示例。】

## 5. 前置章节专用规则【定制:按前置章节实际结构】

典型结构(供参考,按实际裁剪):
1. 产品定位与设计边界:压到 1 页内;
2. 功能结构总览:结构总览表 + 主业务流程清单 + FUN 总表(编号/名称/所在页面/一句话职责);
3. 功能关联关系:REL 表精简为"源→目标:关系一句话";横切约束单列保留全文;
4. 设计决策:逐条"决策 + 一句话理由",未处理的放最前并标 ⚠;
5. 需求功能点总表:REQ 清单和 FP 清单各一张精简表;论证过程**全部删**,映射进溯源附表。

## 6. 篇幅目标【定制:按本文档规模实测校准】

- 每个 FUN:输出 40–100 行(压缩到 30–40%)。**该目标不含字段表/规则表/验收标准三类整表搬运行**(此三类逐行保留,不计入压缩)。
- 全模块成品目标按 34→实际 FUN 数 ×(90–110 行)+ front/附录 行数**实测重算**,不得拍脑袋;历史教训:两层目标不重算会互相矛盾。
- **压不动就不压**:字段表、规则表、验收标准是密度合理的内容,不做二次改写,只删空列。

## 7. 禁止事项

- 禁止新增原文没有的字段、规则、阈值、提示文案。
- 禁止改写 mermaid 图的节点语义(按 §1 第 8 项定死的口径整图删或留,不可画新图)。
- 禁止把"待确认"当成已定稿写进正文。
- 禁止用"等等/类似/如有必要"这类开放措辞——原文没有的模糊化就是失真。
- R 规则、Q 疑点、DEC 决策的**编号一个不能丢**(内容可摘出,编号必须出现在草稿某处)。
- 禁止顺手订正原文的编号错位/口径矛盾(见 §0 第 4 条)。
