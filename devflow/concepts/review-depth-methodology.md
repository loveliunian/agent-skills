# 评审深度方法论 (Review Depth Methodology)

> 本文档是 P0b（PRD 评审）与 P2a（详设评审）共用的深度标准。Gate 脚本按本文档的确定性标记（DF/AW）做机械校验，模板按本文档定义章节结构。三者必须同步演进。

---

## 1. 问题定义：浅评审的三种症状

| 症状 | 表现 | 根因 |
|------|------|------|
| **盲勾** | "业务流程清晰 ✅"这类可无思考勾选的检查项 | checklist 泛化，无操作性探针 |
| **凑数** | 大量"命名不规范/注释缺失"级 nitpick 凑够配额 | 单一数量指标（旧 ≥15 条）激励灌水 |
| **一句话问题** | "分页需考虑大数据量"，无场景、无后果、无法验证 | 问题条目缺少深度字段契约 |

**判定原则：一条评审意见的价值 = 场景具体度 × 后果严重度 × 可验证性。三者缺一即浅层发现。**

---

## 2. 深层发现契约（Deep Finding, DF）

### 2.1 格式

每条深层发现使用独立标题块（不用表格行），便于 Gate 机械校验：

```markdown
#### DF-01 {一句话标题}
- 归属评委：{架构师|后端专家|前端专家|测试开发|DBA}
- 文档位置：§{x.y}
- 触发场景：在【什么业务/操作场景】下，当【动作/事件】发生时
- 影响链：不修复将导致【数据错误/资损/流程阻塞/测试不可行…】的具体传导路径
- 根因类别：缺失定义 | 边界遗漏 | 一致性冲突 | 决策无依据 | 可测性不足 | 性能容量 | 安全权限
- 完善建议：{具体到可执行}
- 验证方式：{修复后如何确认，如：重跑 §9 追溯 / 补充用例 X / H2 执行 DDL}
```

### 2.2 合格标准

| 字段 | 不合格示例 | 合格示例 |
|------|-----------|---------|
| 触发场景 | "并发情况下" | "两个客服同时对工单 #123 执行关闭操作，请求间隔 <100ms" |
| 影响链 | "会有问题" | "两次 update 均成功且状态机未拦截 → 审核记录出现两条互相矛盾的关闭日志 → 对账报表口径分裂" |
| 验证方式 | "修复后检查" | "用 JMeter 5 并发重放该接口，断言 audit_log 仅 1 条" |

- 文档位置必须是 `§数字.数字` 锚点格式，禁止"详见设计文档"。
- 五个必填字段（归属评委/触发场景/影响链/完善建议/验证方式）任一为空，Gate 判为无效 DF。

### 2.3 表层发现（Surface Finding, SF）

允许存在但单独编号 `SF-{nn}`，不计入配额、不阻塞 Gate；单角色 SF > 5 条说明评审深度不足，主持人应在修订轮追问 DF。

## 3. 六类深挖探针

每位评委必须逐类执行并在报告中留痕（探针执行记录表）。**没有跑过探针就输出"通过"属于走过场。**

| # | 探针 | 操作化步骤 | 合格产出 |
|---|------|-----------|---------|
| P1 | **对抗场景走查 (AW)** | 选 ≥N 条"最可能出错"的端到端路径（中途失败/重复提交/部分成功需回滚/越权访问），沿 触发→输入→处理→依赖→结果 逐步推演（覆盖 Web/MQ/定时/批处理等实际形态） | AW 清单（见 §4） |
| P2 | **边界与极端值枚举** | 对每个关键字段枚举：0 / 1 / max / null / 空串 / 超长 / 负数 / 时区 / 精度 / 并发重复提交 / 幂等重放 | 边界枚举表，每个未定义行为 = 1 条 DF |
| P3 | **状态机×异常分支矩阵** | 列出所有状态转移，对每个转移叠加异常（网络超时/下游失败/用户取消/重试），检查设计是否定义回退路径 | 转移×异常覆盖矩阵，空洞 = DF |
| P4 | **跨产物一致性核对** | 两两核对 PRD ↔ 验收点 ↔ 数据模型 ↔ 接口契约 ↔ 权限矩阵 ↔ 前端交互；任何一处名称/口径/取值范围不一致即为一致性冲突 | 差异清单（即使"看似微小"也要登记） |
| P4b | **前置操作反向可达性**（L-P2-005 教训） | 从规则/错误码**反向**追问：凡"先 X 才可 Y/未 X 返回 409"的前置操作，X 必须在接口章有真实端点且有字段级契约（不能只有概览行）；同类操作在不同域的契约密度应对称 | 对每条前置操作给出"端点§x.y + 详定义小节/复用声明"；悬空 = DF（机械防线：s2 §6b rule_operation_closure） |
| P4c | **内容充分性三防线**（L-P2-006/007/008 教训） | ① **机制承接**：设计文档引用的 archive/旧设计中的机制（序列号分配器/降级/退避/幂等键/锁）逐项在新文档核对，丢失=DF；PRD 必填项差集人工核对；② **状态机穷尽**：每个 status 枚举值至少一条进入/退出描述（死状态=DF）、跨表状态组合显式穷举合法/非法；③ **跨文档契约**：jobKey/内部端点/权限码与对端文档及权限矩阵双边对账 | 机制承接清单 / 状态值×组合矩阵 / 跨文档对账表（机械防线：s2 §6c content_sufficiency_probes 三探针） |
| P5 | **决策 Why 链** | 对每个非平凡决策追问：备选方案是什么？为何不选？理由能否指向业务口径/规范条目/量化数据？"经验/习惯/常用/业界都这么做"一律不通过 | DDR 核问记录（详设）/ 决策依据表（PRD） |
| P6 | **数据量与时间演化** | 按当前量 ×10 / ×100 推演：查询计划退化点？索引失效场景？归档策略？统计口径随时间漂移？ | 容量推演结论，风险 = DF |

### 探针 × 角色 主责矩阵

| 探针 | 业务/产品 | 架构 | 后端 | 前端 | 测试 | DBA | 安全 |
|------|----------|------|------|------|------|-----|------|
| P1 对抗走查 | ● | ● | ● | ● | ◆ | ○ | ● |
| P2 边界枚举 | ○ | ○ | ● | ● | ◆ | ● | ○ |
| P3 状态机矩阵 | ● | ○ | ● | ● | ◆ | ○ | ○ |
| P4 一致性核对 | ◆ | ● | ● | ● | ● | ● | ● |
| P5 Why 链 | ● | ◆ | ● | ○ | ○ | ◆ | ○ |
| P6 数据演化 | ○ | ● | ● | ○ | ○ | ◆ | ○ |
| P4c 内容充分性 | ○ | ◆ | ● | ○ | ◆ | ● | ○ |

◆=主责 ●=必做 ○=按需

## 4. 对抗场景走查（AW）规范

```markdown
### 对抗场景走查
- AW-1 场景：{一句话}｜走查路径：{数据→API→客户端→状态 的关键步骤}｜结果：{发现 DF-01 / 无问题，证据：§x.y 已定义回退}
```

- 每条 AW 必须以 `结果:` 收尾，且要么引用 DF 编号、要么引用设计章节锚点作为"已覆盖"证据。
- "无问题"的 AW 同样有价值——它是设计健壮性的正面证据，禁止省略。

## 5. 分层配额（替代旧的"每人 ≥15 条"）

> 旧配额只求数量，激励 nitpick 灌水。新配额区分层次：

| 层次 | P0b（PRD 评审） | P2a（详设评审） |
|------|----------------|----------------|
| 深层发现 DF | 按实际发现；零发现须有核查证据 | 按实际发现；每角色须有 DF 或 ZERO-DF 核查证据 |
| 对抗场景走查 AW | ≥2 条 | ≥3 条 |
| 六类探针执行记录 | P1/P2/P4/P5 必做 | 全部六类必做 |
| 表层发现 SF | ≤5 条/角色 | ≤5 条/角色 |
| 歧义术语决议表 | 必须（或显式声明"无歧义"并附核查证据） | — |
| 零发现结论 | 允许 ZERO-DF，但必须附核查清单、证据锚点和主持人复核 |

---

## 6. 浅层信号黑名单（Gate 可检测）

以下信号出现在评审报告中将导致 Gate FAIL 或 WARN：

| 信号 | 处理 |
|------|------|
| DF 块缺任一必填字段 | FAIL |
| 文档位置非 `§x.y` 格式 | FAIL |
| AW 缺 `结果:` 或既无 DF 引用也无 § 锚点 | FAIL |
| 角色既无 DF 也无 ZERO-DF 核查块 | FAIL |
| 出现"已阅/LGTM/无明显问题/整体没问题"式结论且无核查清单 | FAIL |
| SF 数量超过 DF 数量 | WARN（凑数嫌疑） |

## 7. 与 Gate 和模板的映射

| 方法论概念 | 模板落点 | Gate 校验 |
|-----------|---------|----------|
| DF 块 | 详细设计评审报告-模板 §问题详情；PRD评审-模板 §深层发现 | `p2a_design_review_gate.sh` §3b；`artifact_gate.sh P0b` |
| AW | 两模板 §对抗场景走查 | 同上（计数 + 结果收尾校验） |
| 探针执行记录 | 两模板 §探针执行记录 | 存在性检查 |
| 分层配额 | committee subagent 定义 | 适用角色覆盖与证据闭环 |
| 歧义术语决议表 | PRD评审-模板 | `artifact_gate.sh P0b` |

## 8. 铁律

1. **先跑探针后下结论**：未执行适用主责探针不得给出任何结论标记。
2. **DF 四要素缺一不算深层**：无场景、无影响链、无验证方式的意见降级为 SF。
3. **不以数量凑数**：DF 必须来自可验证场景；SF 超 DF 仍提示凑数风险。
4. **零发现必须举证**："没有问题"本身是需要证据的主张，使用 ZERO-DF 块记录。
5. **Gate 只认确定性标记**：DF/AW 编号与字段由脚本机械校验，主观描述不作为放行依据。
