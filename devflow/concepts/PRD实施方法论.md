# PRD → 详设 → 代码实施 闭环路径

> **对应**：`docs/PRD到代码实施路径.md`（V1.1，2026-08-17）

## 核心原则

| # | 原则 | 含义 | 违反信号 |
|---|------|------|----------|
| 1 | **字段级颗粒度** | 详设必须落到：每个表字段的类型/约束/口径（五列表）；迁移场景 B/C 的字段来源与转换规则在 `docs/数据映射/` 八列映射表 | 评审时无法回答"这个字段从哪来、到哪去" |
| 2 | **准伪代码** | 核心业务流程用结构化伪代码表达，分支挂规则编号，可直接翻译为代码 | 详设只有自然语言段落，开发时重新"发明"逻辑 |
| 3 | **100%设计 + 80%首轮代码** | 冻结后的原子验收点必须100%进入详设；首轮代码准确率目标≥80% | 把20%误差理解为允许20%需求不设计 |
| 4 | **过度设计防线** | 每个设计元素必须回指 PRD、澄清决议、架构不变量、ADR之一 | 出现"预留扩展""将来可能"且无任何权威来源 |
| 5 | **证据优先** | 任何"完成/达标"声明必须附可执行命令的实际输出 | 报告里只有结论没有命令输出 |
| 6 | **文档即契约** | 测试不通过先修文档或先修代码，但终态二者必须一致 | 文档残留过程标注、修订流水账 |

## 指标口径

```
设计覆盖率 = COMPLETE 原子验收点数 / 冻结原子验收点总数 = 100%
首轮代码准确率 = 首轮通过对应测试与独立 Review 的原子验收点数 / 冻结原子验收点总数 >= 80%
```

## 阶段全景

### 第一阶段：试点校准（P0-P6）

| 阶段 | 核心产物 | 出口门控 |
|------|----------|----------|
| P0 需求基线 | 权威来源矩阵 + 原子验收点清单 | 未决P0歧义=0 |
| P1 概设定纲 | 总详设 + 工程事实源 | 服务归属落定 |
| P2 详设 | 模块详设（字段级五列 + 准伪代码） | 设计覆盖率=100% |
| P2 迁移映射 | 逻辑模型 + 数据字典 + 映射表 | 映射覆盖率=100% |
| P3 试点实施 | Flyway + 代码 + 单测 + Seed | 编译绿、单测绿 |
| P5 测试门控 | 独立Review + 业务轨 + 数据轨 | P0=0，双达标 |
| P6 归因修正 | 归因表 + 修订文档/代码 | 首轮准确率≥80% |

### 第二阶段：全量推广（P6 全量执行 + 图谱健康）

| 阶段 | 核心产物 | 出口门控 |
|------|----------|----------|
| P6 全量执行 | 批次计划 + 验收记录 | 全部批次达标 |
| 图谱健康（P4b 后可选） | 索引健康 + 影响面查询 | 图谱就绪或显式回退 |

### 修正循环 / 全量执行 / 图谱健康

| 环节 | 与 devflow 的关系 | 说明 |
|-------------|-------------------|------|
| **P6 修正循环** | 横跨所有 Phase | devflow 任意 Phase 失败后的修正过程，产出归因表 + 修订文档/代码，首轮准确率≥80% |
| **P6 全量执行** | P6 内完成 | 批次计划与 devflow 的部署批次对齐 |
| **图谱健康（P4b 后可选）** | 辅助门控 | 可在 devflow 任意 Phase 触发，用于验证图谱就绪或显式回退，影响面结论必须有图谱健康证据 |

## 附录：门控一票否决

1. P0：运行 `scripts/s0_acceptance_gate.sh`，未决P0或基线不完整即阻断
2. P1：运行 `scripts/s1_fact_sources_gate.sh`
3. P2：运行 `scripts/s2_design_coverage_gate.sh`，设计覆盖率<100%即阻断
4. P2 迁移映射（B/C）：运行 `scripts/s3_migration_mapping_gate.sh`，映射覆盖率<100%即阻断
5. P5：运行迁移证据Gate，业务或数据轨P0>0即阻断
6. P6 首轮准确率：运行 `scripts/s6_first_pass_accuracy.sh`，准确率<80%即阻断
7. 图谱健康（P4b 后可选）：运行 `maintenance/s8_graph_health_gate.sh`，无ready或显式回退证据即阻断影响面结论

详见各阶段 Phase 文件。
