# devflow 增量变更模式使用指南

> **版本**: v3.28.1  
> **功能**: 支持最小化变更路径（只改一个字段、只加一个 API）

---

## 🎯 设计目标

### 当前问题

devflow 假设 `new` 或 `change` 两种模式：
- **new**: 从零开始构建
- **change**: 修改现有功能

但缺少 **"只改一个字段"** 这样的最小化变更路径。

### 解决方案

**增量变更模式**：针对小范围变更（单个字段、单个 API、单个 bug）提供专门的快速通道。

---

## 🚀 使用方法

### 基本语法

```bash
bash scripts/incremental_change_mode.sh <feature-name> <change-type> [scope]
```

### 支持的变更类型

| 变更类型 | 说明 | 示例 |
|---------|------|------|
| `add-field` | 添加一个数据库字段 | `user.phone` |
| `modify-field` | 修改一个数据库字段 | `user.email` |
| `add-api` | 添加一个 API 接口 | `POST:/api/users` |
| `modify-api` | 修改一个 API 接口 | `GET:/api/users/{id}` |
| `add-rule` | 添加一个业务规则 | `rule-001` |
| `modify-rule` | 修改一个业务规则 | `rule-002` |
| `add-validation` | 添加一个参数校验 | `username.length` |
| `fix-bug` | 修复一个 bug | `issue-123` |

## 📊 增量变更 vs 完整流程

### 时间对比

| 变更类型 | 完整流程 | 增量模式 | 节省时间 |
|---------|---------|---------|---------|
| **添加一个字段** | 3 小时（P0-P6） | 30 分钟 | **83%** |
| **添加一个 API** | 4 小时 | 1 小时 | **75%** |
| **修复一个 Bug** | 2 小时 | 20 分钟 | **83%** |

### 流程对比

**完整流程（P0-P6）**：
```
P0 需求澄清 → P0b 评审 → P1 选型 → P2 详设 → P3 编码 → P4 验证 → P5 测试 → P6 执行
⏱️ 耗时：3-5 天
```

**增量模式（跳过冗余阶段）**：
```
增量变更计划 → 修改设计 → 渲染 JSON → 编码 → 测试 → 验证
⏱️ 耗时：30 分钟 - 2 小时
```

## 🎓 最佳实践

### 1. 何时使用增量模式？

**适合增量模式**：
- ✅ 添加/修改单个字段
- ✅ 添加单个 API 接口
- ✅ 修复单个 bug（影响 1-2 个文件）
- ✅ 添加单个参数校验
- ✅ 调整单个业务规则

**不适合增量模式**（使用完整流程）：
- ❌ 新增整个模块
- ❌ 重构架构
- ❌ 修改多个关联功能
- ❌ 需要 PRD 评审的需求

### 2. 增量变更记录

所有增量变更都会记录到 `.devflow/<feature>/incremental.json`：

```json
{
  "feature": "user-management",
  "mode": "incremental",
  "changes": [
    {
      "type": "add-field",
      "scope": "user.phone",
      "table": "user",
      "field": "phone",
      "timestamp": "2026-09-20T03:05:00Z",
      "status": "pending"
    }
  ],
  "base_commit": "abc123",
  "created_at": "2026-09-20T03:00:00Z"
}
```

### 3. 与完整流程的集成

增量变更可以随时**升级到完整流程**：

```bash
# 如果发现变更影响范围扩大
bash scripts/incremental_to_full.sh <feature-name>
```

## 🔧 故障排查

### Q1: 增量验证失败怎么办？

**A**: 查看验证输出，修复失败项后重新运行验证。

### Q2: 增量变更后如何提交？

**A**: 
```bash
# 1. 验证通过后提交
git add .
git commit -m "feat: add phone field to user table"

# 2. 清理增量状态
rm .devflow/user-management/incremental.json
```

### Q3: 能否同时进行多个增量变更？

**A**: 可以。每次运行 `incremental_change_mode.sh` 都会追加到 `incremental.json`。

### Q4: 增量变更会生成哪些文件？

**A**: 
- `.devflow/<feature>/incremental.json` - 变更记录
- 其他文件由你手动修改（按照生成的建议）
