# Phase 6e: PC Web 浏览器自动化测试

> 报告产物：`docs/测试/<feature>-端到端报告.md`（历史英文名 `*-e2e-report.md` 继续可被 Gate 解析，新产物用中文名）。

## 目标

执行 PC Web 的真实浏览器旅程并保留报告。微信小程序和 APP 不进入本文件，分别按 `phases/06c-前端联调.md` 与冻结的 `devflow-client.json` 使用开发者工具、模拟器或真机。

## 门禁口径（v3.27.6 起，L-M01-011）

**定位**：P6 各测试阶段（含本阶段）是**交付把关（final gate），不是缺陷发现阶段**——缺陷的发现在 P3 实现、P3b 评审、P4/P4b 验证已完成；P6 回答的问题只有一个：**功能是否已实现且在真实环境真实运行**。只有真实运行通过才可声明交付。

**把关不等于放水**：P6 暴露的缺陷必须**修复 → 重跑测试 → 循环直到测不出问题（FAIL=0）**才可交付——禁止带病交付、禁止跳过或降低断言标准换取绿灯。每轮修复按铁律 8 重跑同一 Gate 并保留各轮证据（命令、退出码、报告），多轮循环的完整链路进入 `verification.json`；同时回溯上游门禁为何漏过并收紧对应 Gate。

1. **E2E 必须是"真实浏览器 × 真实前端 × 真实后端 × 真实密钥"的实跑**。API 探针、脚本侧独立实现的加密/签名、MockMvc 均不可替代 E2E 证据——它们绕过前端代码路径，证明不了"真实可运行"（参见 L-M01-011：M01 登录 RSA 前端解析必崩，API 探针全绿）。
2. **E2E 用例与 UI/流程同步演进**：登录流程、菜单结构、页面路由发生迁移/裁剪时，同步更新冒烟断言（按钮文案、落点路由、菜单项）。断言对象已不存在的 E2E 视为**失效**，失效 E2E 参与门禁按 FAIL 计，不得以"存在 E2E 文件"充当覆盖证据。
3. **冒烟最小集**：登录（真实密钥链路）→ 登录后落点路由可达（redirect 目标真实存在）→ 核心页面渲染 → 侧边栏菜单与菜单种子一致。
4. E2E 实跑命令、退出码与报告路径必须进入 P6 `verification.json`，与其他测试类证据同等待遇。

## 实施步骤

### Step 1: 环境检查

```bash
# 进入前端目录
cd frontend

# 检查 Playwright 安装状态
npx playwright --version

# 安装 Chromium（如果未安装）
npx playwright install chromium
```

### Step 2: 检查服务状态

```bash
# 检查后端服务是否就绪
curl -s http://localhost:8080/actuator/health | grep -q "UP" && echo "Gateway OK" || echo "Gateway FAIL"

# 检查前端服务
curl -s http://localhost:5173 | grep -q "vite" && echo "Frontend OK" || echo "Frontend FAIL"
```

### Step 3: 执行 E2E 测试

```bash
# 进入前端目录
cd frontend

# 运行所有 E2E 测试
npm run e2e

# 运行特定模块的测试（使用中文命名）
npm run e2e -- 组织架构.spec.ts
npm run e2e -- 权限管理.spec.ts
npm run e2e -- 登录鉴权.spec.ts

# 运行特定用例（按标签过滤）
npm run e2e -- --grep "TC-组织架构-001"
npm run e2e -- --grep "P0"

# 生成 HTML 报告
npm run e2e -- --reporter=html
```

### Step 4: 分析测试结果

```bash
# 查看测试报告
open frontend/playwright-report/

# 查看失败的测试截图
ls -la frontend/test-results/
```

## Playwright 测试执行配置

### 配置文件：playwright.config.ts

```typescript
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './e2e',
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  workers: process.env.CI ? 1 : undefined,
  reporter: [
    ['html', { outputFolder: 'playwright-report' }],
    ['list'],
  ],
  use: {
    baseURL: 'http://localhost:5173',
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
    video: 'retain-on-failure',
  },
  projects: [
    {
      name: 'chromium',
      use: { ...devices['Desktop Chrome'] },
    },
  ],
  webServer: {
    command: 'npm run dev',
    url: 'http://localhost:5173',
    reuseExistingServer: !process.env.CI,
  },
});
```

### 环境变量

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| E2E_ADMIN_USERNAME | 无默认值 | 从seed解析或CI密钥注入 |
| E2E_ADMIN_PASSWORD | 无默认值 | 从受控环境注入，禁止写入文档 |
| E2E_ADMIN_USER_ID | 无默认值 | 从seed解析 |
| E2E_FAILED_SEND_LOG_ID | - | 消息重发测试的失败日志ID |

## 问题发现与修复流程

### 发现问题

```
┌─────────────────────────────────────────────────────────┐
│  E2E 测试执行中...                                       │
│  ✗ TC-ORG-004: 新增单位 - 失败                          │
│    Error: expect(locator).toBeVisible()                  │
│    提示 "新增成功" 未出现                                 │
└─────────────────────────────────────────────────────────┘
```

### 问题分析

1. **检查网络请求**：查看是否发送了正确的 API 请求
2. **检查页面状态**：查看当前页面的实际状态
3. **检查控制台日志**：查看是否有 JS 错误
4. **检查截图**：查看失败时的页面截图

### 修复问题

根据问题类型选择修复方式：

| 问题类型 | 可能原因 | 修复方式 |
|----------|----------|----------|
| 测试用例问题 | 选择器不正确、断言条件错误 | 修改测试用例 |
| 前端问题 | 组件渲染异常、交互逻辑错误 | 修复前端代码 |
| 后端问题 | API 返回错误、接口异常 | 修复后端代码 |
| 环境问题 | 服务未启动、配置错误 | 修复环境配置 |

### 修复后验证

```bash
# 重新运行失败的测试
npm run e2e -- --grep "TC-组织架构-004"

# 运行整个模块的测试
npm run e2e -- 组织架构.spec.ts

# 运行所有测试
npm run e2e
```

## Red Flags

以下情况必须停止并汇报：

| 红旗 | 问题 | 正确做法 |
|------|------|----------|
| 服务未启动 | 后端/前端服务不可用 | 先启动服务 |
| 测试环境配置错误 | 环境变量缺失 | 配置环境变量 |
| 测试用例错误 | 选择器/断言不正确 | 修复测试用例 |
| 严重缺陷发现 | P0/P1 用例失败 | 记录并修复缺陷 |
| **登录失败盲目猜测密码** | 反复尝试 `admin/admin123`、`admin888`、`12345678` 等常见密码 | **禁止**！停止测试，去代码 seed 找正确凭证（见下） |

### 🚨 登录失败时的正确处理流程

**禁止行为**：
- ❌ "尝试凭据 `admin/admin123` 及多个常见密码，均返回 401"
- ❌ 在测试报告里列举 5 个常见密码作为"穷举尝试"
- ❌ 修改 admin 密码为 `admin123` "让测试能过"

**正确行为（按顺序排查）**：

1. **查代码 seed**（铁证）：
   ```bash
   grep -l "username.*admin" backend/<service>/src/main/resources/db/migration/*/<service>/V*.sql
   # 找到 seed 脚本后看 INSERT 语句里的 password_hash 字段 + 注释
   ```
   凭据来源在seed/初始化器中是确定的，但Skill不记录明文；测试时从受控环境注入。

2. **确认 E2E helper 默认值**：
   ```bash
   grep "ADMIN_USERNAME\|ADMIN_PASSWORD" frontend/e2e/helpers.ts
   # 期望：常量从 process.env 读取；缺失时明确BLOCKED，不回退常见密码
   ```

3. **确认环境是否执行 seed**：
   ```bash
   # E2E 主库是否跑了 Flyway V*.sql 到最新？
   # 数据库方言与启动 profile 一致？（h2 / postgresql / oracle / kingbase）
   ```

4. **确认密码是否被手工改过**：
   ```bash
   # 如是，用环境变量覆盖
   cd frontend
   E2E_ADMIN_PASSWORD='<新密码>' npx playwright test e2e/*.spec.ts
   ```

5. **如仍失败，BLOCKED 转 SKIP 必须记录**：
   - 测试报告中"阻塞原因"列必须写**真实的 3 个候选原因**（参考上面 1-3 步）
   - 不允许写"凭据失效"四个字了事
   - 详见 `references/severity-tiers.md` §"审计错误（盲猜凭证）" — 触发 = P0

## 关键原则

1. **先环境后测试** - 确保服务就绪后再运行测试
2. **按优先级执行** - P0 > P1 > P2
3. **失败即停** - 发现问题立即分析，不要跳过
4. **截图留证** - 失败时自动截图保存证据
5. **修复验证** - 修复后必须重新运行测试验证
6. **凭证可追溯** - 测试账号/密码必须从代码 seed 或 E2E helper 中获取，禁止盲猜
