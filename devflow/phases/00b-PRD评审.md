# Phase 0b: PRD评审 (PRD Review)

## 目标

- 确保PRD文档完整、清晰、可执行
- 评审需求的可行性
- 识别潜在风险和技术难点
- 确认各方对需求理解一致

---

## 评审维度

| 维度 | 检查点 |
|------|--------|
| **完整性** | 功能描述是否完整？边界条件是否覆盖？ |
| **清晰性** | 需求描述是否清晰无歧义？术语是否统一？ |
| **可测试性** | 需求是否可验证？验收标准是否明确？ |
| **可行性** | 技术上能否实现？有没有实现风险？ |
| **一致性** | 与现有系统是否一致？有没有冲突需求？ |
| **优先级** | 需求优先级是否合理？ |

---

## PRD评审Checklist

### 信息完整性
- [ ] 背景和目标清晰

- [ ] 功能描述详细
- [ ] 业务流程清晰

### 验收标准
- [ ] 成功标准明确
- [ ] 失败场景覆盖
- [ ] 性能指标量化
- [ ] 安全要求明确

### 可行性
- [ ] 技术可行性评审
- [ ] 资源可行性评审
- [ ] 时间可行性评审

## 评审角色

> 角色问题库与 DF/AW 输出契约见 `subagents/prd-review-committee.md`；深度规范见 `concepts/review-depth-methodology.md`。

| 角色 | 职责 |
|------|------|
| **业务专家** | 口径一致性、歧义术语决议（主责 P4 一致性核对、P5 Why 链） |
| **技术负责人** | 可实现性、隐性成本、实时性/批量/导入导出承诺核问 |
| **前端交互** | 四态覆盖（加载/空/错/无权限）、表单联动、幂等交互 |
| **测试** | 可验证性断言翻译、边界枚举（主责 P2）、并发预期 |
| **安全合规** | 权限矩阵、脱敏、审计留痕是否显式需求 |

产品经理为被评审方，只答疑不评审（当事人回避）。

## 评审输出

| 输出 | 说明 |
|------|------|
| 评审记录 | 评审会议纪要 |
| 歧义术语决议表 | 每条歧义 → 决议口径 + 决议人 |
| 边界条件枚举表 | 未定义行为登记为 DF |
| 对抗场景走查 AW | ≥2 条，每条以 `结果:` 收尾 |
| 深层发现 DF | 按实际发现登记（五字段缺一无效）；零发现须附 ZERO-DF 核查记录，禁止凑数 |
| 表层发现 SF | ≤5 条/角色，不计配额不阻塞 |
| 评审结论 | 通过/不通过/有条件通过 |
| 修改清单 | 需要修改的内容 |

## 验收Checklist

- [ ] 评审会议已召开
- [ ] 所有角色已参与评审
- [ ] 四类探针（P1/P2/P4/P5）执行记录齐全
- [ ] 歧义术语全部决议（或"无歧义"+证据）
- [ ] 问题清单已输出（DF 按实际发现；每角色有 DF 或含核查实质的 ZERO-DF 记录）
- [ ] AW ≥2 条
- [ ] 评审结论已确认
- [ ] 产品经理已确认通过

## Gate 检查

```bash
bash "$SKILL_ROOT/scripts/artifact_gate.sh" P0b <feature>
```

| 检查项 | 通过条件 |
|--------|----------|
| 报告存在且非空 | ≥10 行 |
| 深层发现 DF | 块数按实际发现；每个 `#### DF-` 块五字段（归属评委/触发场景/影响链/完善建议/验证方式）非空 |
| 单角色证据 | 每角色有 DF，或含核查实质的 ZERO-DF 记录（核查范围/证据锚点/验证方式） |
| 对抗场景走查 | `- AW-` 条目 ≥2 且含 `结果:` |
| 探针执行记录 | P1/P2/P4/P5 章节存在 |
| 歧义术语决议表 | 存在且无未决议行（或显式"无歧义"声明） |
| 边界条件枚举 | 章节存在 |
| 遗留问题 = 0 | `grep -cE '遗留\|未解决\|待修复' docs/需求/<f>-PRD评审.md = 0` |
| 无占位符 | `grep -cE 'TODO\|TBD' docs/需求/<f>-PRD评审.md = 0` |
| 浅层信号 | "已阅/LGTM/无明显问题"式结论无核查清单 → FAIL |
