# Phase 6d: 压测

> 报告产物：`docs/测试/<feature>-压测报告.md`（历史英文名 `*-load-report.md` 继续可被 Gate 解析，新产物用中文名）。

## 目标

通过压力测试验证系统的性能指标，确保满足非功能性需求。

---

## 压测指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 响应时间 P50 | < 200ms | 中位数响应时间 |
| 响应时间 P95 | < 500ms | 95%请求的响应时间 |
| 响应时间 P99 | < 1000ms | 99%请求的响应时间 |
| QPS/TPS | > 1000 | 每秒处理请求数 |
| 错误率 | < 0.1% | 失败请求比例 |
| CPU使用率 | < 80% | 峰值时CPU占用 |

---

## 压测工具选择

| 工具 | 适用场景 | 特点 |
|------|----------|------|
| **wrk** | 简单HTTP压测 | 轻量、命令行、单机器 |
| **JMeter** | 复杂场景、分布式 | 功能强大、可视化 |
| **k6** | 脚本化测试 | JavaScript脚本、结果可集成 |
| **Locust** | Python脚本 | Python脚本、分布式支持 |

## wrk压测（推荐快速验证）

### 基础压测

```bash
# 基础GET请求压测
wrk -t12 -c400 -d30s http://localhost:8080/api/v1/users

# 参数说明:
# -t12: 12个线程
# -c400: 400个连接
# -d30s: 持续30秒
```

### 带参数的POST压测

```bash
# 创建wrk脚本
cat > post-test.lua << 'EOF'
wrk.method = "POST"
wrk.body   = '{"username":"user","email":"user@test.com","password":"Pass123!"}'
wrk.headers["Content-Type"] = "application/json"
EOF

# 执行压测
wrk -t12 -c400 -d30s -s post-test.lua http://localhost:8080/api/v1/users
```

## k6压测（现代方案）

### 测试脚本

```javascript
// load-test.js
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '2m', target: 100 },  // 2分钟内升到100用户
    { duration: '5m', target: 100 },  // 保持100用户5分钟
    { duration: '2m', target: 0 },    // 2分钟内降到0
  ],
  thresholds: {
    http_req_duration: ['p(95)<500'], // 95%请求<500ms
    http_req_failed: ['rate<0.01'],  // 错误率<1%
  },
};

export default function () {
  const res = http.get('http://localhost:8080/api/v1/users/1');
  check(res, {
    'status is 200': (r) => r.status === 200,
    'response time < 200ms': (r) => r.timings.duration < 200,
  });
  sleep(1);
}
```

### 运行

```bash
k6 run load-test.js
```

## Red Flags 🚩

以下情况必须停止并汇报：

| 红旗 | 问题 | 正确做法 |
|------|------|----------|
| 性能不达标 | "差不多就行" | 必须达到指标 |
| 无基准数据 | 直接高压 | 必须先测基准 |
| 单次测试 | 不稳定 | 必须多次验证 |
| 不监控资源 | 只看QPS | 必须监控CPU/内存 |

---

## 常见问题处理

| 问题 | 解决方案 |
|------|----------|
| QPS上不去 | 分析瓶颈（DB/网络/代码） |
| 错误率上升 | 分析错误原因 |
| 内存泄漏 | 分析堆快照 |
| CPU 100% | 分析热点代码 |

---

## 关键原则

1. **单变量测试** - 一次只改变一个因素
2. **预热充分** - 启动后预热2-5分钟
3. **数据隔离** - 压测数据与生产数据分离
4. **监控完整** - 监控CPU、内存、网络、数据库
5. **多次验证** - 同一测试运行多次确保结果稳定
