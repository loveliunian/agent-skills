# Phase 6b: TestContainers集成测试

> 报告产物：`docs/测试/<feature>-集成测试报告.md`（历史英文名 `*-integration-report.md` 继续可被 Gate 解析，新产物用中文名）。

## 目标

使用TestContainers启动真实的数据库和中间件容器，进行真实的集成测试。

## TestContainers简介

TestContainers是一个Java库，提供轻量级、一次性的Docker容器，用于自动化集成测试。

**优势：**
- 使用真实数据库（MySQL/PostgreSQL/Oracle等）
- 测试结果更接近生产环境
- 隔离性好，每个测试类独立的容器
- 自动清理，无副作用

## 配置示例

### PostgreSQL容器

```java
@Testcontainers
class UserRepositoryTest {

    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15-alpine")
        .withDatabaseName("testdb")
        .withUsername("test")
        .withPassword("test");

    @DynamicPropertySource
    static void properties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
        registry.add("spring.jpa.hibernate.ddl-auto", () -> "create-drop");
    }

    @Test
    void testSaveAndFind() {
        // 使用真实数据库测试
    }
}
```

### 多容器测试（数据库 + Redis）

```java
@Testcontainers
@SpringBootTest
class UserServiceWithCacheIntegrationTest {

    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15-alpine");

    @Container
    static GenericContainer<?> redis = new GenericContainer<>("redis:7-alpine")
        .withExposedPorts(6379);

    @DynamicPropertySource
    static void properties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
        
        registry.add("spring.data.redis.host", redis::getHost);
        registry.add("spring.data.redis.port", () -> redis.getMappedPort(6379));
    }
}
```

## Red Flags 🚩

以下情况必须停止并汇报：

| 红旗 | 问题 | 正确做法 |
|------|------|----------|
| Docker未启动 | 不检查环境 | 必须先验证Docker |
| 容器启动失败 | 忽略错误继续 | 必须解决启动问题 |
| 测试相互污染 | 数据不清理 | 每个测试清理数据 |
| 超时不处理 | 增加超时时间 | 分析为什么慢 |

---

## 常见问题处理

| 问题 | 解决方案 |
|------|----------|
| Docker未启动 | 确保Docker Desktop运行中 |
| 容器启动慢 | 使用较小的镜像或启用reuse |
| 端口冲突 | TestContainers自动处理端口映射 |
| 测试超时 | 增加超时时间或优化镜像 |
| 内存不足 | 限制容器数量，使用更小镜像 |

---

## 关键原则

1. **环境一致性** - 测试环境尽可能接近生产
2. **数据隔离** - 每个测试使用独立数据
3. **自动清理** - 测试结束后自动清理容器
4. **可重复** - 测试可多次运行，结果一致

| 检查项 | 通过条件 |
