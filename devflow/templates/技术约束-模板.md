# 技术约束契约 - {FeatureName}

> 本文件是 P0 的冻结事实源。`MUST_USE`、`MUST_NOT_USE` 和固定版本属于硬约束，不能被 P1 的加权评分或 Agent 自主决策覆盖。
> Gate 只解析下方机器契约块，**不从自然语言推断合规**（"未引入 X"这类描述不参与判定）。

## 机器契约（唯一机读事实源；字段格式勿改）

<!-- DEVFLOW:CONSTRAINTS
constraint_id=TC-TECH-001
type=MUST_USE
subject=workflow-engine
required_product=camunda
required_version=7.24.0
status=FROZEN
confirmed=true

constraint_id=TC-TECH-002
type=MUST_NOT_USE
subject=workflow-engine
required_product=FlowCore
status=FROZEN
confirmed=true
DEVFLOW:END -->

字段说明：

| 字段 | 约束 |
|---|---|
| constraint_id | `TC-XXX-000` 格式，全局唯一 |
| type | `MUST_USE` / `MUST_NOT_USE` |
| subject | 约束对象（能力域，如 workflow-engine） |
| required_product | MUST_USE=必须采用的产品；MUST_NOT_USE=禁止出现的产品 |
| required_version | MUST_USE 时的最低/固定版本（可选） |
| status | 必须 `FROZEN`；`DRAFT` 会被所有 Gate 阻断 |
| confirmed | 必须 `true`（用户明确批准后才能置 true） |

> 如果没有技术硬约束，机器契约块必须只写两行：`constraint_set=NONE` 和 `confirmed=true`；不得省略本块。

## P1 选型绑定（人读展示；机读绑定块写在设计决策记录中）

| constraint_id | selected_option | compliance | evidence |
|---|---|---|---|
| TC-TECH-001 | camunda 7.24.0 | PASS | `backend/pom.xml` 依赖坐标 |
| TC-TECH-002 | camunda | PASS | 依赖树扫描无 FlowCore 坐标 |

> 注意：`selected_option` 必须写**实际选定的产品名**。禁止写"未引入 X"这类否定描述充当选型——合规判定由机读绑定块中的 `selected_product` 决定。

## 变更规则

- 任何选型与 `MUST_USE` 或 `MUST_NOT_USE` 冲突时，P1 立即 `BLOCKED`。
- 只有用户明确批准、更新 PRD/本契约并重新冻结（status=FROZEN + confirmed=true）后，才能恢复。
- P2 详设必须逐条引用 `constraint_id`；P3 依赖/config 与 P4b 代码对账使用同一组 `constraint_id`。
- 本文件冻结后，P1 Gate 会校验 state 中冻结的文件 SHA（`devflow-state.sh constraints-freeze`）。
