# 详细设计模板路由器

> 模板 ID：`详细设计-模板`（路由器）；模板版本：`{{template_version}}`（写产物时以被选用模板的 frontmatter 为准）
> 本文件不再内嵌任何版本的模板正文（v0.1 目录版 / v0.2 摘要版已废弃删除）。
> 直接生成产物时，把对应模板全文复制为起点，不要复制本路由器。

## 模式来源与选择

> 单文档（monolith）还是总分文档（total）**已在 P1 设计决策记录决策并冻结**（设计决策记录
> 《详设文档结构决策》，机检行 `design_doc_structure_mode=`）。P2 只按下表取模板，
> 不在详设中重新决策；结构不适用时回 P1 走变更。

| P1 冻结 mode | 判定来源 | 模板 | Gate（s2_design_coverage_gate.sh） |
|------|----------|------|------|
| **monolith**（单文档，默认） | P1 选型 `design_doc_structure.mode=monolith` | `详细设计-完整版-模板.md` | `--mode=monolith` |
| **total** · 总文档 | P1 选型 `mode=total`（模块多/跨服务/多团队并行） | `详细设计-总分总文档-模板.md` | `--mode=total` |
| **total** · 分文档 | P1 选型 `planned_docs[]` 中 doc_mode=sub 的登记 | `详细设计-总分分文档-模板.md` | `--mode=sub` |

## 硬性规则

1. 产物头部必须写所复用模板的**精确 ID 与版本**（`> 模板 ID：`…`` / `> 模板版本：`…``），Gate 按此校验，任意字符串不通过。
2. 产物必须包含五个语义锚点：`data-model` / `api-contracts` / `business-rules` 在详设正文；`acceptance-traceability` 在 `需求追溯-模板` 文档（`<feature>-需求追溯.md`）；`implementation-handoff` 在 `实现交接-模板` 文档（`<feature>-实现交接.md`）——章节号仅用于展示，锚点是 /plan、/build 与 Gate 的定位正本。
3. 追溯矩阵逐列非空：PRD锚点(#) / 页面§ / 接口§ / 数据§ / 规则(§或R编号) / 测试用例(TC-) / 状态 COMPLETE。
4. 详设必须逐条引用 P0 冻结的 `constraint_id`（技术硬约束）。
5. 以下为完整版必含章节：§10.1 成熟组件复用清单、§10.2 公共服务与公共组件抽取登记、§11 异常处理、安全与性能设计；规范遵循（命名/开发/注释基线）在设计决策记录《规范遵循》（`anchor: standards-compliance`）；数据库设计决策（DDR+迁移）在独立文档 `数据库设计决策-模板`（`anchor: design-decisions`，管线 `--db-doc` 渲染）、需求追溯矩阵在 `需求追溯-模板`（`anchor: acceptance-traceability`，`--trace-doc`）、实现交接在 `实现交接-模板`（`anchor: implementation-handoff`），随详设一并产出。

## 调用方式

```bash
# 单体
bash "$SKILL_ROOT/scripts/s2_design_coverage_gate.sh" docs/详细设计/<feature>-详细设计.md docs/需求/<feature>-验收点.md --mode=monolith
# 总分总文档 / 分文档
bash "$SKILL_ROOT/scripts/s2_design_coverage_gate.sh" <design.md> <criteria.md> --mode=total   # 或 --mode=sub
```
