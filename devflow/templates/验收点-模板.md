## 拆分原则

> **一个验收点 = 一个行为 = 一个测试用例**

| 规则 | 说明 | 正例 | 反例 |
|------|------|------|------|
| 单一行为 | 一个验收点只描述一个可观察行为 | "新增记录成功返回 ID" | "新增和编辑记录" |
| 可验证 | 必须能用 API/UI 自动化验证 | "返回 200 状态码" | "用户体验好" |
| 可失败 | 必须能明确判断成功或失败 | "字段为空时返回 400" | "字段处理正确" |
| ID 格式 | `M-{模块号}-F{功能号}-A{验收点号}` | `M-01-F01-A01` | `验收点1` |

## 拆分步骤

```
┌──────────────────────────────────────────────────────────────┐
│  Step 1: 阅读 PRD，识别所有功能点（功能 = F）                 │
│  Step 2: 每个功能点拆分为原子验收点（A）                      │
│  Step 3: 每个验收点标注可验证方式（API / UI / 单元测试）      │
│  Step 4: 标注 PRD 原文锚点（章节/行号）                       │
│  Step 5: 评审 → 冻结（FROZEN）                                │
│  Step 6: 移交 P2 详设，作为需求追溯文档矩阵源（`<feature>-需求追溯.md`） │
└──────────────────────────────────────────────────────────────┘
```
