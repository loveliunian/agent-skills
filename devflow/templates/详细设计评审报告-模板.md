## 对抗场景走查（AW ≥3 条，每条 场景/走查路径/结果 三段非空，结果的 §锚点必须真实存在）

> 走查路径以「触发→输入→处理→依赖→结果」实例化为 Web / MQ / 定时任务 / 批处理等实际形态，
> 不固定为「数据→API→客户端→状态机」；结果的引用必须能解析到详设真实章节（§x.y）或本报告 DF 编号。

- AW-1 场景：{中途失败/重复提交/部分成功回滚/越权访问…}｜走查路径：{触发→输入→处理→依赖→结果 的实例化步骤}｜结果：{发现 DF-xx / 无问题，证据：§x.y}

### 问题详情

#### 深层发现 DF（每条独立成块，五字段缺一 Gate 判无效）

```markdown
#### DF-01 {一句话标题}
- 归属评委：{架构师|后端专家|前端专家|测试开发|DBA}
- 文档位置：§{x.y}（禁止"详见文档"）
- 触发场景：在【什么业务/操作场景】下，当【动作/事件】发生时
- 影响链：不修复将导致【具体后果】的传导路径
- 根因类别：缺失定义|边界遗漏|一致性冲突|决策无依据|可测性不足|性能容量|安全权限
- 完善建议：
- 验证方式：{修复后如何确认：重跑追溯/补充用例/H2 执行 DDL…}
- 严重性：P0/P1/P2
- 状态：OPEN|CLOSED
```

无深层发现时，每个角色必须写 `ZERO-DF` 核查块，列出核查范围、证据锚点和验证方式。

**DF 修复记录：**
- [ ] DF-01：修复完成 → 验证通过（验证方式：____）
