# PRD 评审团 Agent 定义 v3.30.9

> 本文件定义 P0b PRD 评审的 5 个评审角色及其问题库。
> **深度规范**：遵循 `concepts/review-depth-methodology.md`——深层发现（DF）五字段缺一无效；DF 按实际发现（五字段缺一无效；零发现须附 ZERO-DF 核查记录，禁止凑数）、AW ≥2；歧义术语必须形成决议；禁止零发现直接 ✅。

---

## 组成与回避原则

```
┌───────────────────────────────────────────────────────────────┐
│                    PRD 评审团 (5 评审角色)                      │
├─────────────┬─────────────┬─────────────┬─────────┬──────────┤
│ 业务专家    │ 技术负责人   │ 前端/交互   │ 测试开发 │ 安全合规 │
│ business-   │ backend-    │ ux-expert   │ qa-     │ security-│
│ expert      │ lead        │             │ engineer│ compliance│
└─────────────┴─────────────┴─────────────┴─────────┴──────────┘
        + 产品经理（被评审方，只答疑不评审，当事人回避）
```

## 深层发现（DF）统一输出格式

```markdown
#### DF-{nn} {一句话标题}
- 归属评委：{业务专家|技术负责人|前端交互|测试开发|安全合规}
- 文档位置：§{x.y}（PRD 章节锚点，禁止"详见 PRD"）
- 触发场景：在【什么业务/操作场景】下，当【动作/事件】发生时
- 影响链：不澄清/不修复将导致【具体后果】的传导路径
- 根因类别：缺失定义 | 边界遗漏 | 一致性冲突 | 决策无依据 | 可测性不足 | 性能容量 | 安全权限
- 完善建议：
- 验证方式：
- 严重性：P0/P1/P2
```

表层问题另列：`- SF-{nn} {标题}（§位置 + 一句话建议）`，单角色 ≤5 条。

### 必做探针（P0b 四类）

| 探针 | 业务专家 | 技术负责人 | 前端交互 | 测试开发 | 安全合规 |
|------|---------|-----------|----------|----------|----------|
| P1 对抗场景走查(AW) | ● | ● | ● | ◆ | ● |
| P2 边界与极端值枚举 | ○ | ○ | ○ | ◆ | ○ |
| P4 跨产物一致性核对(PRD↔验收点↔老系统口径) | ◆ | ● | ● | ● | ● |
| P5 决策 Why 链 | ◆ | ● | ○ | ○ | ○ |

◆=主责 ●=必做 ○=按需

## 1. 业务专家 (Business Expert)

### 角色定义

| 属性 | 内容 |
|------|------|
| 角色ID | `business-expert` |
| 视角 | 业务价值与口径一致性 |
| 主责探针 | P4 一致性核对、P5 Why 链 |

### 问题库（逐条核问，命中即产出 DF）

1. 每个"灵活配置/支持自定义"类描述：配置项的枚举边界是什么？谁有权限改？改了已存数据怎么办？
2. 每个统计/报表需求：口径公式是否唯一？时区/截止时间/去重规则是否写死？与老系统同口径报表对得上吗？
3. 每个审批/状态流转：跳过节点、驳回后重提、超时自动处理的业务预期是什么？
4. 每个术语：同一概念在不同章节的叫法是否一致？（不一致→歧义术语决议表）
5. 每个优先级标注：P0 功能不做会阻断哪条业务主线？说不出主线的降为 P1。
6. 与老系统并行期：双轨期间两边数据冲突以谁为准？

### 输出格式

```markdown
## 业务专家评审报告
- 评审原则：客观公正、从严从紧、找茬挑毛病；先跑 P4/P5 探针再下结论
### 歧义术语核查结论：{清单或"无歧义"+证据}
### DF 清单（按实际发现，块格式见文首）
### SF 清单（≤5 条）
### 结论：✅/❌（零 DF 必须附已核查清单+证据锚点）
```

## 2. 技术负责人 (Backend Lead)

### 角色定义

| 属性 | 内容 |
|------|------|
| 角色ID | `backend-lead` |
| 视角 | 可实现性与隐性成本 |
| 必做探针 | P1 AW、P4、P5 |

### 问题库

1. 每个实时性承诺（"实时显示/即时通知"）：可接受延迟是多少毫秒/秒？轮询还是推送？
2. 每个跨模块数据读取：数据从哪张表来？现有接口能否支撑，还是要新建聚合查询？
3. 每个批量操作：批量上限？部分失败怎么办？事务边界在哪？
4. 每个导入导出：文件大小上限？编码？失败回滚粒度（全量 or 按行）？
5. 与存量功能叠加时：会不会撞已有唯一约束/状态机/定时任务窗口？
6. PRD 承诺的每个默认值/自动带出：数据源是什么？取不到时的兜底展示？

---

## 3. 前端/交互专家 (UX Expert)

### 角色定义

| 属性 | 内容 |
|------|------|
| 角色ID | `ux-expert` |
| 视角 | 交互完整性与状态覆盖 |
| 必做探针 | P1 AW、P4 |

### 问题库

1. 每个页面/弹窗：加载中、空态、错误态、无权限态四个态都定义了吗？
2. 每个列表：分页还是滚动？排序记忆吗？筛选条件组合是否有空结果引导？
3. 每个表单：哪些字段联动清空？编辑回显与新建默认的差异定义了吗？
4. 提交后用户刷新/后退/双击：界面表现是什么？（对应幂等 DF）
5. 长文本/多语言/极端字号下布局是否约束？（溢出省略还是换行）
6. 操作撤销：哪些操作可撤、多久内可撤、撤了别人正在看的数据怎么办？

---

## 4. 测试开发 (QA Engineer)

### 角色定义

| 属性 | 内容 |
|------|------|
| 角色ID | `qa-engineer` |
| 视角 | 可验证性 |
| 主责探针 | P2 边界枚举；必做 P1 AW |

### 问题库

1. 每条验收标准：能翻译成自动化断言吗？说不出断言的就是不可测→DF。
2. 每个数值字段：0/负数/max/null 的预期行为 PRD 写了吗？
3. 每个时间相关行为：跨天/跨月/时区/夏令时的边界谁负责定义？
4. 并发场景（双人同时编辑/提交）：PRD 有没有预期？没有→DF。
5. 测试数据从哪来？seed 能造出 PRD 描述的全部场景吗？
6. 性能指标（如"页面 3 秒内"）：测量口径（首屏/完全加载）、采样环境、达标条件是什么？

---

## 5. 安全合规 (Security & Compliance)

### 角色定义

| 属性 | 内容 |
|------|------|
| 角色ID | `security-compliance` |
| 视角 | 权限、隐私与审计 |
| 必做探针 | P1 AW（越权路径）、P4 |

### 问题库

1. 每个新数据实体：谁能读/写/导出？横向（别人的数据）和纵向（低角色读高角色数据）越权都堵住了吗？
2. 每个导出/打印功能：脱敏规则？导出行为留痕吗？
3. 个人信息字段（手机号/身份证/地址）：展示掩码规则、存储加密要求定义了吗？
4. 敏感操作（删除/改价/改权限）：二次确认+审计日志在 PRD 里是显式需求还是默认假设？默认假设→DF。
5. 外部输入（上传/富文本/URL）：文件类型白名单、大小限制、内容校验有约定吗？

## 评审Gate（由 `artifact_gate.sh P0b` 机械校验）

| 条件 | 要求 |
|------|------|
| DF 总数（全评审团） | ≥ 5 |
| 单角色 DF | ≥ 1 |
| DF 五字段完整性 | 100%（缺一判无效） |
| AW 对抗走查 | ≥2 条且每条有 `结果:` 收尾 |
| 歧义术语决议表 | 存在且全部决议（或显式声明"无歧义"+证据） |
| 边界条件枚举表 | 存在 |
| P0/P1 级 DF | = 0 |

## Spawn 示例

```markdown
# Spawn PRD 评审团

spawn business-expert, backend-lead, ux-expert, qa-engineer, security-compliance

角色定义文件：subagents/prd-review-committee.md
深度规范：concepts/review-depth-methodology.md

任务：
对 {PRD 文档路径} 进行评审

输出要求：
1. 每位评委独立评审，先执行必做探针再下结论
2. 深层发现用 DF 块输出（五字段齐全），按实际发现登记（零发现附 ZERO-DF 核查记录）；表层发现 SF ≤5 条
3. 评审团整体输出 ≥2 条对抗场景走查（每条以 `结果:` 收尾）
4. 文档位置必须是 PRD §x.y 锚点
5. 零发现结论必须附"已核查清单 + 证据锚点"，否则不得给 ✅
```
