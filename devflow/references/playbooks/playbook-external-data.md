# 外部系统数据依赖专项评审

> 规则来源：集成契约清单（内部约定，无外部时效性）
> 核验日期：2026-08-26 ｜ 责任人：每次 P2a 前由评审主持人对照官方最新文档复核一次
- 内部集成契约约定（无外部时效源）；对接方官方 API 文档链接须登记于 docs/references/<系统名>/

> 触发条件：PRD/详设中出现外部/第三方系统对接、接口文档、数据源依赖。
> 核心原则：**没有 API 文档或字段字典，就不允许该依赖进入 P2 详设的接口设计**——"先写代码再问对方要什么"是集成项目最大的返工来源。
> 每项给出 ✅ / ❌（附 DF-xx）/ N-A（附理由）。

## 契约文档

- [ ] **API 文档存在性**：对方系统的接口文档（URL/附件）是否已拿到并归档到 `docs/references/<系统名>/`？文档版本号与更新通知机制？
- [ ] **字段级数据契约**：能否给出每个使用字段的**字段字典**（名称/类型/枚举值/空值语义/长度上限）？"给到哪些数据"必须落到字段清单，而不是一句"会推数据给我们"。
- [ ] **样例报文**：真实环境样例请求/响应报文至少各 1 份归档？

## 鉴权与环境

- [ ] **鉴权方式**：AppKey/AppSecret、OAuth、证书？凭证由谁持有、存放在哪（禁止入库入仓）、如何轮换？
- [ ] **环境矩阵**：联调/生产双环境地址？IP 白名单申请流程与时限？
- [ ] **测试数据**：联调环境的可用测试账号与造数能力？

## 流量与一致性

- [ ] **配额限流**：QPS/日调用量上限？超限返回什么（错误码/429）？我方重试与退避策略？
- [ ] **数据同步模式**：推送（回调）还是拉取（轮询）？频率、增量标识字段、时区与时间精度？
- [ ] **幂等与去重**：回调重发场景下我方幂等键设计；乱序到达的处理？
- [ ] **分页与排序**：对方分页规范（page/token 游标）、排序稳定性保证——翻页期间数据变更是否可能漏/重？

## 异常与边界

- [ ] **错误码映射表**：对方错误码 → 我方用户话术 + 系统动作（重试/告警/人工介入）的映射表是否建立？
- [ ] **超时预算**：单次调用超时设置、熔断阈值、对总链路耗时的影响占比？
- [ ] **降级方案**：对方不可用时 PRD 行为定义（只读缓存/功能停用/整体降级）与用户提示文案？
- [ ] **数据回压**：批量同步时对方吞吐不足的处理（分片/夜间窗口）？

## 责任与合规

- [ ] **责任边界**：数据不一致时的对账责任方；联合排查的联系人/升级路径/响应 SLA？
- [ ] **敏感数据合规**：传输字段中是否有个人信息/商业敏感数据？脱敏要求、存储期限、跨境限制？
- [ ] **变更协同**：对方字段/接口变更的通知周期与我方适配承诺（写入维护条款）？
