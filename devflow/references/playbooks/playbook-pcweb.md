# PC Web 专项评审

> 规则来源：团队前端基线（浏览器矩阵/CSP）
> 核验日期：2026-08-26 ｜ 责任人：每次 P2a 前由评审主持人对照官方最新文档复核一次
- 浏览器兼容基线：https://caniuse.com/（按项目 browserslist 复核）

> 适用：scope.frontend = pc-web。每项给出 ✅ / ❌（附 DF-xx）/ N-A（附理由）。

## 兼容与适配

- [ ] **浏览器矩阵**：Chrome/Edge/Firefox/Safari 的版本下限是否写入 PRD 并被前端构建目标（browserslist）覆盖？
- [ ] **分辨率策略**：设计稿基准宽度（1280/1440/1920）？响应式断点还是固定布局+横向滚动？
- [ ] **企业环境**：是否需兼容 360 安全浏览器等 Chromium 定制内核或低版本 IE 只读降级？

## 安全

- [ ] **传输与证书**：全站 HTTPS、证书续期责任人、HSTS 是否启用？
- [ ] **CSP/CORS**：内容安全策略基线；跨域接口的 CORS 白名单维护方式？
- [ ] **XSS/CSRF**：富文本输入（若有）的净化方案；写操作的 CSRF Token 或 SameSite 策略？

## 性能与 SEO

- [ ] **首屏预算**：FCP/LCP 目标值与监控手段（PRD 是否量化）？
- [ ] **SEO 范围**：是否要求搜索引擎收录（决定 SSR/预渲染 vs 纯 SPA）？登录后系统可 N-A。
- [ ] **静态资源**：CDN 域名、缓存指纹策略、大文件下载走独立带宽？

## 部署与运维

- [ ] **部署形态**：nginx 静态托管 + API 反代？灰度方案（按 cookie/权重）？
- [ ] **i18n/无障碍**：多语言范围与切换点；无障碍（键盘可达/对比度）是否有硬性要求？
