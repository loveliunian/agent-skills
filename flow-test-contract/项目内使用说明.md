# 项目内使用说明（团队共享副本）

> 本目录是 `flow-test-contract` skill 的**项目内共享副本**（v1.7.5），随仓库分发，
> 团队成员 clone 后即可直接使用，无需各自安装。
> skill 的完整介绍见同目录 [README.md](README.md)，agent 主入口见 [SKILL.md](SKILL.md)。

## 与个人安装版的关系

| | 路径 | 说明 |
|---|---|---|
| **唯一事实源** | `~/.agents/skills/flow-test-contract` | 维护者本地；改动只在此处进行 |
| **项目共享副本**（本目录） | `.codex/skill/flow-test-contract` | 随 git 分发；**只读使用，勿直接改** |

副本已移除 `sync-to-tools.sh`（该脚本按设计只能从源目录执行）。

## 团队成员怎么用

```bash
cd <项目根>
SKILL=.codex/skill/flow-test-contract
FTC_PY=python3; python3 -c "import yaml, jsonschema" 2>/dev/null || FTC_PY="uv run --with pyyaml,jsonschema python3"

# 0) 自检（会话快检 --quick 秒级；版本发布/深度审计跑全量 selftest.py，全量计数以实跑输出为准）
$FTC_PY "$SKILL/templates/selftest.py" --quick

# 1) 立契 → 2) 校验 → 3) 生成 → 4) 演练/执行 → 5) 结论
#    完整命令见 SKILL.md 工作流各步；把命令里的 $SKILL 指向本目录即可
```

依赖：`python3` + `pyyaml` + `jsonschema`（或装 `uv` 走 `uv run --with` 回退）；
浏览器通道另需 `node`/`playwright-cli`。

## 产物落哪里（不进本目录）

- **交付物** → `docs/<流程名>/自动化测试/`（契约、`生成件/`、`对比测试/<run-id>/`）
- **私有运行态**（通道配置、gate 证据库）→ `$SKILL/runtime/<项目键>/`，
  或用 `FLOWTEST_RUNTIME_DIR` 指定；**含内网地址与端点，切勿提交**
- **凭据** → 只写 `$SKILL/runtime/<项目键>/env`（私有运行态、权限 0600，绝不入库；统一默认密码需显式 `FLOWTEST_ALLOW_DEFAULT_PWD=1`），契约里只允许 `env: CURRENT_<账号>_PWD` 引用

## 更新副本（维护者操作）

skill 升版后，用项目内同步脚本一条命令搞定（自动排除 runtime/、同步后跑副本自检）：

```bash
bash scripts/sync-project-skills.sh                      # 同步全部共享 skill（含副本自检）
bash scripts/sync-project-skills.sh flow-test-contract   # 只同步本 skill
bash scripts/sync-project-skills.sh --check              # 门禁：只校验不写（CI / 提交前）

git add .codex/skill/flow-test-contract && git commit -m "chore(skill): 同步 flow-test-contract vX.Y.Z"
```

脚本行为：
- 排除 `runtime/`（内网地址/证据库）、`sync-to-tools.sh`（只能从源目录执行）、`__pycache__`、`.DS_Store`
- 同步后强制 `diff -r` 字节校验 + `runtime/` 兜底拦截；副本 selftest 不全绿则**拒绝**并提示别提交
- `--check` 零写入，退出码 0=一致 / 1=漂移 / 2=用法错误或未登记 skill

建议接入 CI：把 `bash scripts/sync-project-skills.sh --check` 作为门禁，防止有人只改副本不改源。

## 注意

- 副本内改动**不会**回流到源，也会被下次同步覆盖——需求请提给维护者改源目录
- 老系统为**生产环境**：非只读操作前务必确认影响面（见 `references/lessons-learned.md` L15/L16）
