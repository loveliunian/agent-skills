## 原子拆分准则

- 一条验收点描述一个可独立判断的行为及其可观察结果。
- 写清前置条件、触发操作和预期结果；避免“正常工作”“体验良好”等无法判定的表述。
- 每个 PRD 来源行只映射到结果语义一致的 AC；按功能组或 REQ 批量关联不算逐场景映射。一个来源行拆成多个 AC 时，在映射表中列出全部 AC。
- 每条 AC 只验证一个起始状态和一个结果。成功/失败、确认/取消、提交/不提交、有效/无效输入分别列点；不要在同一条里执行多个请求，却只断言其中一个结果。
- 前置条件要写明角色、隔离数据、字段值、对象关系和初始状态；操作要写明页面动作或已确认的接口调用；结果要指出可观察的页面、响应或持久化变化。时钟、作业、故障注入、短信或加密等依赖须写出确定性 test-only fixture。fixture 尚未实现时，明确标为“待实现测试夹具”，并写出入口、数据、注入点、断言与清理步骤；不得称其已存在或已运行。业务结果或 fixture 步骤无法由来源确定时，才标为未决并阻止冻结。
- 被拆分的历史合并 ID 如需保留，明确标为“仅迁移追溯、不可执行”，并在来源说明中列出承接它的具体新 AC。
- 每条关联 PRD 需求 ID 和原文位置，并标明适合的验证方式（API、UI、单元、集成或其他）。
- 使用稳定 ID（如 `AC-001`）。复杂行为的不同结果或分支拆成不同验收点。
